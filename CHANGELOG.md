# Changelog

What changed between released versions, for a person reading it.

**One line per release while this project has no outside users.** That is a decision rather than
an omission: a changelog is written for somebody who does not have the repository, and until
someone is upgrading between two published versions there is nothing longer to answer. It grows
when there is a reader for it to grow for.

Commits are in `git log`; the reasoning behind a design decision stays in the document that
carries the decision. A changelog repeating either becomes a second carrier and goes stale.

## Unreleased

Nothing published yet. **The first entry gets written when the first version is tagged** — a
changelog line dated in advance is a claim about something that has not happened.
